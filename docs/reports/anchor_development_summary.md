## 1. 核心结论

本次演进并非在早期旧版 Native 布局上继续微调间距，而是以固定的 Eclipse ELK 源码为行为参考，**从头独立实现了完整的分层布局与边界超边正交布线流水线（P0–P5）**，并将其收敛提取为无外部依赖、可离线直接调用的 `H08` 静态 ES 模块包。

截至最终签收，约定范围内的视觉可读性、几何正确性、工作台集成与 Windows 离线发布门禁均已通过验证：

- **视觉验收通过**：用户明确签收了 `SOP015`（`_5426_` / `_5404_`）独立输入树、`EQ012`（`_1471_`）、11 组机制测试场景，以及 `sop001`、`eq006`、`dp002` 三个分层抽样综合网表。
- **全量测试与严格门禁**：签收时完整单元测试 808/808 通过；47 个完整节点映射网表在 45000 ms Worker 限时与严格几何校验下 **47/47** 通过，硬违规数为 **0**。
- **产品全链路集成**：Single / Compare 双视图、Adjust 手工覆盖隔离与 `Reset` 恢复、离线 SVG 导出、异步 Worker 取消与过期结果隔离、标签页会话恢复以及 Windows 离线发布包均通过实测。

**结论定性**：在已声明的平面门级网表支持范围与本次验收语料上，`H08` 达到了约定的 ELK 级可读性水平（注：该结论不外推为“任意通用拓扑均与 ELK 视觉等价”或“所有软性指标全面超越 ELK”）。

## 2. 早期旧版 Native 方案未能达标的根因

早期旧版 Native 布局的问题并非“子树之间少了几个像素的留白”，而是**分层（Layering）、排序（Ordering）、纵向对齐（Alignment）与正交布线（Routing）各阶段之间的图模型不一致**。一旦前序阶段丢失了跨层拓扑与端口约束，仅靠后置推开节点或加大空白，根本无法恢复已经被打散的逻辑分支结构。

以 2026-09-24 固定的 `SOP015` Focused 3/3 基线（57 个节点、60 条边）为例：

| 评估指标 | ELK 0.11.1 参考 | 早期旧版 Native |
| --- | ---: | ---: |
| 视觉列数 | 12 | 7 |
| 总导线长度 | 18654.75 | 41274 |
| 逻辑边交叉数 | 28 | 228 |
| 物理线段交叉数 | 28 | 187 |

旧实现的逻辑边交叉数高达参考值的 **8.14 倍**；单纯把子树间距调大 96 px 完全无法改善这些全局拓扑纠缠。这促使开发策略从“局部修补”彻底转向“固定上游源码审计 + 逐相位因果取证 + 完整流水线重实现”。

## 3. 对标重构的完整相位机制（P0–P5）

算法行为研究固定对标 Eclipse ELK 提交 `28e5173243cab0cf4e2c9816c803bc0d5c47ab24`；产品内同输入视觉对比则使用仓库本地化的 `elkjs 0.11.1`：

| 流水线阶段 | H08 核心职责 | 对原理图可读性的决定性影响 |
| --- | --- | --- |
| **P0 规范化输入** | 建立规范化身份（canonical ID）、几何尺寸测量、固定端口顺序与不可变快照 | 彻底消除输入数组排列顺序或显示名变化对布局结果的干扰 |
| **P1 有向破环** | 有界加权贪心破环（Weighted Greedy Cycle Breaker），保留逻辑方向恢复信息 | 为含反馈环的时序网表建立可分层的有向无环骨架 |
| **P2 秩分配（分层）** | 基于紧树（Tight-tree）与单纯形网络（Network Simplex）计算最优层级跨度 | 从根源上缩短长边跨度，避免后续通过后置挪动节点硬凑层级 |
| **Proper Graph 构建** | 长边虚拟节点拆分（Long-edge splitting）、反向端口处理与超边虚拟节点合并 | 确保跨层排序器与正交布线器看到一致的相邻层拓扑结构 |
| **P3 交叉最小化** | 固定端口双分配器、双向扫层、Forster 约束求解、交叉计数与 H08 分组候选 | 保持多输入扇入树的分支相对顺序与视觉连续性 |
| **P4 纵向坐标分配** | 四方向 Brandes–Köpf（BK）对齐块构建、冲突标记与平衡压紧 | 将主干通路保持在水平对齐块上，而非逐个节点孤立塞入顶部空隙 |
| **P5 正交超边布线** | 边界超边构建、精确依赖图与关键环拆分（Critical split）、槽位分配与层宽投影 | 将节点纵向坐标与层间通道容量联合转化为无重叠正交走线 |
| **逻辑恢复与硬校验** | 恢复逻辑边血统（lineage）、生成物理线网树并执行 `layoutValidator` 硬约束校验 | 确保分支不断裂、不错误合流，且绝不向 UI 交付半成品几何 |

## 4. 开发过程中的关键技术转折

### 4.1 从“看最终截图”转向“定位首个相位分歧”
冻结源网表输入、Provider 输入、配置选项与代码哈希，借助固定的 Java Phase Oracle 导出上游每个处理器执行后的中间图快照，沿 `P0 → P5` 逐阶段比对并定位首个可解释的决策分歧，配合节点重命名与数组随机打乱测试验证不变性。

### 4.2 诚实记录并回退未达标的单项试验
- **显示名脱钩**：早期发现显示名称参与排序会导致仅修改标签也改变布局，因而引入独立的结构排序摘要；但单改排序键曾导致 `EQ` 分支质量退步，故如实记录失败并回退。
- **隐式端点身份与物理干线膨胀的矛盾**：为每条逻辑边分配独立的隐式源端口身份虽能修复长边链混并问题，但单独启用时会导致高扇出网络（如时钟与复位）的物理走线通道成倍膨胀。
- **局部聚拢与交叉预算的权衡**：仅在原槽位内强行聚拢同组节点会推高交叉数，相关候选被严格交叉预算拒绝，未采取放宽阈值强行放行的方式。

### 4.3 H08 的核心突破：逻辑身份严格独立，物理锚点精确共享
`H08` 在 P0–P4 完整保留每条逻辑边与端口的独立规范化身份及血统（lineage）；而在 **P5 正交布线阶段**，仅针对**“同一物理线网（same physicalNetId）、同一节点、同一侧（side）、精确相同局部锚点坐标（anchor）”**的端点建立额外的共享邻接关系（scratch adjacency），从而让同源扇出分支自然共用同一条物理主干通道，而不同线网、不同节点或不同引脚坐标的连线绝不混并。

同时，在 **P3 排序阶段**结合拓扑派生的显式成员提示、结构排序键、固定候选集与单位扫层（unit-sweep），并让 P3 的视觉带宽预测（group-band forecast）与 P5 的最终层宽投影共用同一套几何测量函数，从而有效避免了“逻辑秩连续，但因跨列折算在最终画面上被拆成多列”的问题。相位对照取证证明，上述物理锚点共享仅发生在 P5，未篡改 P0–P4 的上游语义。

### 4.4 攻克 47 例全图回归的性能热点
针对早期全图回归中暴露的超时瓶颈（如 41079 节点、93556 端口、46782 边的 `DP020`），在不放大 45 秒门限、不缩减图规模、不启用折叠、不放宽几何校验的前提下，定点优化了 P2 内部树状态查询、P5 依赖图身份构建、空间索引查询及 P1 首成员查找等純算法复杂度热点，并通过差分测试证明优化前后的计算结果逐字段完全一致。

### 4.5 从研究原型收敛为纯静态离线模块
将全部算法收敛至 `src/layout/anchor_layered/h08.js` 唯一静态实现（研究对比工具亦直接调用该静态模块），并对 6 个代表性产品图逐字段核对几何输出与最终 SVG，确保克隆仓库后即可直接通过浏览器原生 ES Module 导入运行。

### 4.6 产品工作台异步接线加固
在接入真实工作台时，修复了“调度器仅按 `'elk'` ID 判断异步性”与“异步布局完成前统计面板读取空图”两处边界问题，统一改为由 Provider 声明 `executionMode: "async"` 并在工作区维护显式 `Pending` 状态；同时将已退役的 22 个旧版 Native 源文件彻底移出 `src/`。

## 6. 当前已知限制与边界声明

- **支持拓扑范围**：面向平面门级网表、固定左右侧端口及已验收语料，并非上游 ELK 全量配置选项的完整移植。
- **显式拒绝不支持的组合**：分组视觉带宽预测对带分组的自环图（grouped self-loop）与合并秩列（merged rank columns）设有显式拦截，遇到不支持输入时直接给出诊断报错，绝不静默返回残缺图形。
- **超大图交互策略**：单个同步相位内部在检查点响应取消，浏览器端通过独占 Worker 提供强制终止；面对数万节点超大图时，仍推荐优先使用 `Search-first` 与 `Focused` 局部视图。
- **软性指标权衡**：导线长度、交叉数、通道留白与标签可见性之间存在客观折中，硬违规为 0 并不意味着任意未见过的极端拓扑都能获得完美视觉排布。
- **旧版归档隔离**：早期旧版 Native 实现仅留在 `tests/reference/retired_native_layered/` 供历史追溯，绝不作为运行时隐藏回退；UI 层的失败降级链明确固定为 `H08 → ELK → Simple`。
