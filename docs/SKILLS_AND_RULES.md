# 项目专用 Skill 与文档维护规范

## 1. 目的

本项目在演进过程中沉淀了一系列领域专用的开发工作流与约束，例如：

- 如何解析结构化 Verilog（Structural Verilog）并保留双名称标识。
- 如何在缺乏 Liberty（`.lib`）时推断标准单元门类型与引脚方向。
- 如何设计并验证原理图（Schematic）交互与工作区生命周期。
- 如何量化和校验 SVG 正交布局与布线质量。
- 如何维护零构建、纯离线的第三方依赖与跨平台单文件发布包。

这些规范需要稳定记录在版本库中，避免散落在临时对话记录里。

## 2. 文档与 Skill 存放位置

项目专用的 AI 辅助开发技能（Skill）统一存放在：

```text
docs/skills/<skill-name>/SKILL.md
```

公共设计规范、系统架构与阶段工程计划存放在：

```text
docs/DESIGN_SPEC.md
docs/ARCHITECTURE.md
docs/PLAN.md
docs/STAGE_<N>_PLAN.md
```

仓库根目录的 `AGENTS.md` 是 AI 编码代理与新贡献者的自动发现入口，仅保留跨领域、必须无条件遵守的核心工程约束，并路由链接至上述详细文档与对应 Skill。具体领域细节不在 `AGENTS.md` 与 `SKILL.md` 之间重复堆砌。

若日后需要将某项项目 Skill 提升为全局通用 Skill，应从 `docs/skills/` 中挑选已充分验证的稳定版本进行安装，切勿将尚处于试验阶段的规则直接写入全局配置目录。

## 3. Skill 编写要求

每个 `SKILL.md` 必须包含以下结构：

- **可被工具解析的 YAML Frontmatter**：包含 `name` 以及清晰覆盖触发场景的 `description`。
- **适用场景**：明确何时应当激活该技能。
- **必读上下文**：开始修改代码前必须预先阅读的文档清单。
- **核心工作原则与实现约束**：输入输出契约、分层边界与禁止事项。
- **验证矩阵**：不同模块改动对应的最低验证要求。

**职责区分**：Skill 用于指导可复用的开发与验证流程，不能替代项目路线图。长期演进路线写入 `docs/PLAN.md`，各阶段任务拆解写入 `docs/STAGE_<N>_PLAN.md`，模块分层边界写入 `docs/ARCHITECTURE.md`，界面与交互准则写入 `docs/DESIGN_SPEC.md`。

## 4. 文档维护与变更准则

- 修改 `SKILL.md` 前，请确认其描述的是可复用的工程规范，而非一次性任务日志。
- 修改 `docs/DESIGN_SPEC.md` 前，请评估是否与现有 UI 交互行为存在冲突。
- 修改 `docs/ARCHITECTURE.md` 中的模块契约或边界时，请检查是否需要同步更新 `README.md`、`docs/PLAN.md` 及对应阶段计划。
- 引入任何新的开发工具或运行时依赖时，必须明确说明其离线运行方式与许可证合规策略。

## 5. 受控环境下的远程推送故障处理

在受控 Agent 环境（如带有推送审批服务的沙箱环境）中执行 `git push` 时，若审批服务在 Git 命令真正执行前因网络或连接中断拒绝了操作，请遵循以下处理步骤：

1. 不要将审批连接中断误判为 Git 仓库损坏或 GitHub 远端故障，切勿擅自篡改提交历史、远端 URL 或认证配置。
2. 先执行 `git status --short --branch` 确认本地分支仍领先于远端分支；必要时通过 `git log -3 --oneline` 核对待推送的提交记录。
3. 向用户明确说明失败发生在推送审批阶段，并在获得用户再次授权后原样重试 `git push origin <branch>`。
4. 推送返回成功后，再次核对分支状态；仅当确认本地分支不再领先远端时，才向用户报告推送完成。
5. 严禁尝试通过非授权脚本、替代命令或外部接口绕过推送审批机制。

## 6. 编码前必读清单

在动手编写或修改任何功能代码之前，必须依次阅读：

1. `AGENTS.md`
2. `docs/PLAN.md`
3. 当前阶段对应的 `docs/STAGE_<N>_PLAN.md`
4. `docs/ARCHITECTURE.md`
5. 若改动涉及界面、SVG 渲染、布局或交互，必须额外阅读 `docs/DESIGN_SPEC.md`。
6. 若改动涉及自动化工作流、Agent 规则或领域核心逻辑，必须额外阅读 `docs/SKILLS_AND_RULES.md` 与 `docs/skills/netlist-schematic/SKILL.md`。

## 7 错误日志开发与验收要求

2026-11-18 起，新增功能、缺陷修复和发生变更的异步用例必须同时交付可定位的错误日志及失败路径验证。适用于本次触及的代码边界，不要求借单项功能重写整个仓库。现有实现见 [架构中的过程日志与错误诊断](ARCHITECTURE.md#过程日志与错误诊断)，本节规定后续开发的完成标准。

### 7.1 记录责任与信息

领域算法返回结构化 diagnostic 或保留原异常抛出；拥有该操作生命周期的用例/工作区边界负责向既有 Process Log 记录一次。通过窄回调注入记录能力，不能让 parser、领域算法或公共 application 反向导入 `app/processLog.js` 或依赖 DOM。全局异常监听仅作兜底，不能替代主动捕获处的上下文。

每条失败日志必须能回答“哪次操作、哪个对象或范围、在哪个阶段、为什么失败、当前状态如何处理”：

| 内容 | 必须提供的信息 |
| --- | --- |
| 基础字段 | 沿用 `timestamp / level / phase / message / details`；phase 使用已注册阶段，业务动作放 `details.operation` |
| 关联与分类 | 稳定的事件或诊断 code，操作关联 ID；异步操作带 job/request 与 session 标识，避免只靠时间猜归属 |
| 操作上下文 | 可用时带文件名/格式、document 与 revision、module/occurrence、Single 或 Compare 侧、view mode/scope、provider |
| 原始异常 | `details.error` 保留原始抛出值；Error 保留 name、message、stack、code、cause 和结构化 diagnostic；跨 Worker 传输保留等效异常信息，不能只重建 message |
| 定位与规模 | 可用时带行列、相关对象 ID、数量、关键归一化选项、预算/耗时及截断原因；大列表只记总数和有界样本 |
| 处理结果 | 标明是否保留旧画布、回滚候选、返回部分结果或降级；后续恢复成功可用相同关联上下文记录 |

字段只记录该操作实际掌握的信息，不填造假的对象、堆栈或来源。记录上下文须通过 `foundation/log_details.js` 的脱敏和预算控制；检查必要字段在脱敏后仍可读。该工具会过滤含 `source` 的字段名，非敏感元信息使用语义明确的 `fileName`、`documentRevision` 等字段，不能为了排障全面放开原始源码字段。

### 7.2 级别和有界行为

- `error`：当前有效操作失败，无法交付其预期结果。可恢复的持久化失败、预算截断、映射冲突等按实际影响使用 `warning`，同时给出恢复或部分结果状态。
- 无搜索结果、无路径、未发现结构和有效空子图是业务结果，使用必要的 `info` 或不记录；不能当成异常。
- 主动取消和被新请求替代的任务不报错；需要追踪时使用有界 `debug` 摘要，不弹出错误提示，不污染新会话。
- 同一失败由一个拥有者记录，保留现有全局去重与日志接收端重入保护。连续自动保存失败合并，恢复后记录一次，避免刷屏。
- 不在逐节点、逐边、候选搜索内循环、pointer/wheel 每次事件中追加详细日志。阶段完成记录计数摘要，进度使用现有合并机制；保留日志容量和详情预算。
- 不记录完整 BLIF/Verilog、完整图、Session/Scene、用户输入全文或凭证。错误详情和 JSONL 导出保持相同的有界脱敏策略。
- 日志不修改源对象、不改变异常传播、降级、路由/布局结果或 Simple 冻结输出。记录器故障不能覆盖原始异常或导致递归报错。

### 7.3 每项变更的完成标准

在任务计划中列出所触及的失败、警告/部分结果、取消和恢复场景，以及各自的记录边界和上下文；实现时与功能同批提交。可预期失败至少有一条实际边界的注入测试，核对 code/operation、归属、异常信息和旧状态保留。涉及 Worker 时验证原始堆栈/诊断跨线程后可读；涉及异步切换时验证旧请求不会把错误挂到新图。

同时验证未制造噪声：正常空结果和主动取消不产生 error，同一异常不重复报告，超限记录可序列化且有截断提示，日志故障不遮蔽业务异常。仅检查 `console.error` 被调用或日志条数大于零，不足以通过。

对发生变更的用户工作流，浏览器验收必须实际打开 Log 详情，并复制或导出 JSONL，确认与界面失败相符、必要字段没有在序列化/脱敏中丢失。已有公共日志基础设施测试可复用；只有新增失败类型或未覆盖边界才扩展，避免为每个普通辅助函数重复建立日志测试。
