# SSH 工作台开发需求与验收标准

2026-11-21 拆分。**首版 R01–R13 已完成，npm 与 Linux ELF 已通过 A1–A6。** [首版实测记录](remote_workbench_v1_results.md)。 本文用于分派开发任务和判定交付。公开命令、参数、简写和 AIG 行为以[开发计划第 3、4 节](remote_workbench_commands.md)为准。

**首版交付**是工程师用一条 SSH 转发，在本地两个页面上查看服务器的网表和 AIG。工程师能从网页选文件，也能从启动终端或 EDA Tcl 增量加载。**完整版交付**是同一套命令覆盖现有工作台的全部操作，并在四种启动器上得到相同的业务结果。

## 1. 首版开发任务（P0–P4）

| R02 · P1 | Node 交互终端与进程生命周期 | R01 | 在 SSH TTY 中运行 `npm start`，同一终端出现提示符，可连续执行 `pages` 和文件命令。独立 CLI 通过 state 文件连接同一服务。非交互启动器 stdout 只输出约定的 ready 记录。执行 stop 后端口和控制通道关闭，其他服务继续响应 |
| R03 · P1 | 页面注册、选择与重连 | R02 | 打开两页后 `pages` 返回两个不同 ID。在启动终端 `use` 第一页，另一个 shell 用 `--page` 指向第二页，交替发送命令，回执和页面实际变化均对应目标。多页未选时返回候选。刷新重连归原页，复制标签页分配新 ID。关闭已选页后下一条命令明确失败，剩余页无变更 |
| R04 · P1 | 命令队列、取消、重试及完成回执 | R03 | 用可控暂停点依次停在文件读取、页面接收、业务提交前，核对 `job status/wait`。提交前取消后没有业务变更。同 ID 同参重发只产生一次提交，同 ID 异参返回冲突。服务已转发但页面回执丢失时能区分“结果未知”和“已失败”，重新连接不会把旧操作派给新页 |
| R05 · P1 | Netlist 打开、追加模块和时序 | R04 | 使用第 3 节的输入，先打开 top，再追加 extra，模块列表从 1 项变为 2 项。先打开报告 T1，再追加 T2，top 可同时查到两条约定的 Slack。重新打开单模块文件后列表再次只有该文件的模块。不可读的追加文件返回错误，之前的模块和时序仍可查询 |
| R06 · P2 | Linux 单文件启动器、交互终端和独立 CLI | R01–R05 | 将 ELF 单独部署到验证目录，以相同输入重跑 R02–R05。比较模块名、时序值、目标页关系和错误分类。用不同本地端口转发也能连接。服务与 CLI 在无 Node 运行时依赖的环境中完成该流程 |
| R07 · P2 | Tcl 连接与命令返回 | R04–R06 | 同一 Tcl 脚本分别连接 npm 服务与 ELF，用 `::ngb::Cmd` 向某页追加带空格及中文路径的文件。成功 dict 可读取目标和结果。失败可由 `catch` 取得稳定 errorCode。原有 `Start/Status/Stop` 的调用和进程所有权校验通过既有回归 |
| R08 · P3 | AIG 集合、追加和原子提交 | R01，端到端依赖 R04 | 打开图 A，再通过 `add` 或 `aig add` 加入 B。图数从 1 变 2，A 仍活动，A 中已有对象引用有效，Graphviz 调用增量为 **0**。一次显式追加“合法 C、损坏 D”时新增图数为 **0**，回执标出 D 失败、C 未提交。同 request ID 重试后数量仍正确 |
| R09 · P3 | 选择 AIG、保存每图状态和切图隔离 | R08 | 用图选择器与 `module open` 分别切换同名文件。按名字选择返回两个候选，按 ID 选择准确。A、B 可各自拥有 `n0`，搜索范围和来源分别正确。切回时恢复各自选区、视口、roots、Show Path。让 B 的首次布局失败，A 继续可用，B 仍可重试 |
| R10 · P3 | 多 AIG 存档、恢复与资源回收 | R08、R09 | 打开旧 v1/v2 单图存档，各恢复为 1 个活动条目。保存双图并刷新，图顺序、稳定 ID、活动图和每图视图状态恢复。制造存储配额不足，当前内存中的图可操作，警告可查，刷新不会恢复已淘汰的旧设计。单次平移提交重写的未变源码记录数为 0 |
| R11 · P4 | 服务器根目录、目录分页和路径补全 | R02、R06 | 用两个浏览根测试进入子目录、返回父目录、名称过滤、分页与 Tab 补全。记录文件访问，补全只枚举当前层。网页访问根外目标、无权读取的文件、其他页面的文件句柄时均返回失败，页面和回执不包含文件内容 |
| R12 · P4 | 网页服务器选择器与各文件入口 | R05、R08、R11 | 仅在服务器创建输入文件。本地网页可选文件完成打开网表、追加网表、追加时序、追加 AIG。选择器显示目标页、动作及适用的 Compare 侧。本机选择、粘贴和拖放原用例通过。取消选择时业务提交数为 0。混合批次逐文件报告结果，显式 AIG Add 按 R08 整批提交 |
| R13 · P4 | 服务器导出与浏览器下载 | R04、R11 | 从已支持的视图生成同一 SVG，服务器文件与浏览器下载均可打开，图中包含目标设计的对象。已有同名输出默认拒绝覆盖。显式允许覆盖后模拟写入中途失败，旧文件内容逐字节相同，临时文件被回收。服务器写完才返回成功，浏览器回执准确表示已触发下载 |

R08 的集合与解析测试可在 R06、R07 完成前开发。首版验收需在 Node 和 Linux ELF 上对照。涉及完整命令尚未交付的查询，可用已有 UI 独立读取结果，例如在 Inspector 核对 Slack。每个异步任务随开发项交付其失败日志和用例。

## 3. 首版现场验收脚本

**环境与输入。** 在 SSH 服务器创建临时目录，将其中一个目录设为浏览根。输入只存在于服务器。用一条 SSH 本地转发，刻意选择与服务端不同的本地端口。在本地浏览器打开两个标签页，并记录 `pages` 返回的真实编号。以下 pN 表示网表页，pG 表示 AIG 页。两个启动器使用相同的初始数据和独立的干净会话。

| 文件 | 准备方式和预期值 |
| --- | --- |
| `top.v`、`extra.v` | 前者只声明模块 `top`，输入 `a` 经一个 BUF 驱动输出 `y`。后者只声明模块 `extra`。两个设计使用不同模块名以直接验证追加 |
| `T1.rpt`、`T2.rpt` | 均使用 `@module top` 和表头 `point at rt slack`。T1 唯一数据行是 `a 0.10 0.20 0.10`，T2 唯一数据行是 `y 0.30 0.25 -0.05` |
| `base/top.blif`、`eco/top.blif` | 前者取[映射名示例](../../examples/aig_mapped_names.blif)，包含 PI `n0` 和 PO `n4`。后者创建平坦 AND，输入 `n0 n1`，输出 `z_eco`。两文件 basename 和一个输入同名，输出可区分 |
| `shared_cone.dot`、`broken.blif` | 使用[现有合法 DOT](../../tests/fixtures/aig/shared_cone.dot)。损坏的 BLIF 令一个输出引用未声明且无驱动的信号，确保能稳定触发解析或语义错误 |

| 步骤 | 操作 | 现场通过标准 |
| --- | --- | --- |
| A1　连服务 | 用 `npm start` 启动，转发并配对后打开 pN、pG，命名并从 SSH 终端执行 `pages` | 两个不同 ID 对应两个窗口。同一终端仍可输入下一条命令 |
| A2　网表追加 | 在 pN 网页从服务器打开 `top.v` 和 `T1.rpt`。在终端选 pN 后 `add extra.v`，再从独立 Tcl 调用对 pN 执行 `timing add T2.rpt` | `module list` 包含 top、extra，重选 top 后 Inspector 或 `timing show` 读到 a = +0.10、y = −0.05 的 Slack。pG 的来源、选区和视口与操作前一致 |
| A3　同页保留两图 | pG 从服务器打开 base 文件，再从该页选择“追加 AIG”加载 eco 文件，用 `module list` 查询 | 返回 2 个不同图 ID，活动图仍为 base。仅用文件名切换时收到两个候选。按 eco ID 选择后能搜到 `z_eco`，切回 base 后能搜到 `n4` |
| A4　原子性与重试 | 对 pG 的一次 `aig add` 同时传合法 DOT 和损坏 BLIF。随后只传合法 DOT，用同一 request ID 连续提交两次 | 失败后图数仍为 2、活动 ID 不变，错误指向损坏文件。合法请求及其重试指向同一新增图 ID，最终图数为 **3** |
| A5　刷新与断开 | 在 pG 的两张图分别设置选区/缩放，刷新后切图核对。随后先在终端选 pG，再关闭 pG，向其发送一次追加 | 刷新后恢复原图 ID、活动图及各自视图。关闭后追加返回目标不可用，pN 仍只有 top、extra，时序值保持 A2 的结果 |
| A6　切换启动器 | 停止 Node 服务，用单文件 ELF 启动新服务，重新取得页 ID，运行相同流程和同一份 Tcl 脚本 | 两轮的模块集、两项 Slack、图数、图来源、选区归属和失败分类一致。PID、随机请求号、端口与页 ID 只按本轮引用关系对照 |

## 4. 如何判定完成

- **首版。** R01–R13 各自的通过条件有证据，A1–A6 在真实浏览器和两种 SSH 服务上通过。R01 验证全量目录，首版的执行覆盖按本里程碑支持的命令统计。Tcl 脚本必须断言返回值，网页须独立核对可见结果。
- **完整版。** R01–R24 全部通过。按主计划 §3.1 至 §3.8 的唯一命令数分别核对 **16、25、34、33、15、24、7、26**，合计 **180**，五个简写另计。每条命令对应一个拥有者、一个适用上下文成功用例和至少一个边界用例。每个可操作 UI 意图都能追溯到命令。进程启停、宿主交互、服务器读写按自身入口验收，页面操作用 UI、终端、独立 CLI 与 Tcl 对照。
- **证据。** 每项记录需求编号、提交版本、启动器与环境、测试名称、输入、预期/实际值、结果和日志位置。失败保留最小复现和原始错误的脱敏详情。平台跳过、未运行和失败分别记录为待验，验收通过需有对应运行结果。
- **性能边界。** 首版已有两项明确计数断言，即 R08 的后台 Graphviz 调用增量和 R10 的未变源码重写数。其他容量或耗时阈值沿用仓库已有配置。新预算在相应批次先记录同输入基线、配置值及选择理由，再按该值执行边界与超限用例。

完整版的层次和结构用例分别取自[层次设计样例](../../examples/module_hierarchy_demo.v)和 [AIG 结构分析样例](../../examples/aig_structure_demo.blif)。
