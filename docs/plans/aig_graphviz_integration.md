# AIG 主界面接入计划

日期：2026-11-14。状态：待实施。本轮只编制计划，不修改运行时代码。

代码检查基线：`9efb8c7`（v1.4.1 工作区）。视觉和格式依据：[mockturtle 风格选择](../research/aig_mockturtle_style.md)、[带名称的 DOT / BLIF 同图实跑](../research/aig_dot_blif_consistency.md)。研究原型的 12 项检查已通过；它不是生产导入器，也不能直接作为浏览器运行时。

## 1. 交付目标与首版范围

在现有主界面增加 AIG 浏览路径，支持：

1. 导入 **ABC 的 AIG `write_dot` 输出**与**平坦组合 AND/NOT BLIF**。
2. 图中保留 PI/PO 原始名称，例如 `a/b/c/d`、`y/shared/masked`；内部使用稳定显示编号，并能追溯原 DOT ID 或 BLIF 信号名。
3. 两种格式还原为同一个 AIG 模型，统一由 Graphviz `dot` 布局，使用 mockturtle 风格：BT、逻辑深度分组、椭圆 AND、正倒三角 PI/PO、样条和箭头、虚线反相。
4. 支持单位 AND 深度的关键路径高亮、按引用数的扇出高亮。开关和阈值变化不改变布局。
5. 复用左侧 Navigator、主画布与右侧 Inspector，完成概况与对象列表、名称搜索定位、选择与连接追踪、分析详情、平移缩放、SVG 导出，以及基础视图状态恢复。
6. 现有门级网表的导入、Single/Compare、Focused、Adjust、时序、Liberty、Cell Config、保存恢复和布局选择维持原行为。

首版 AIG 使用 Single / Whole 浏览；搜索定位到现有节点，不要求裁剪逻辑锥。暂不启用 AIG 的节点拖动/尺寸修改/Adjust、AIG Compare、层次展开、门级时序导入或逻辑优化。这些能力通过当前文档的 capability 控制，不能全局禁用现有网表功能。

范围索引：AIG before/after Compare、Compare 默认左右分屏，以及 Netlist cone / Whole / Compare 转 AIG 已单独记入 [后续需求备忘](aig_followup_roadmap.md)。这些事项不加入本计划的 P0–P5，也不在本轮修改 Compare 默认方向。

BLIF 首版支持 `.model/.inputs/.outputs/.names/.end`、注释、续行，以及能还原为至多二输入 AND、NOT、BUF、常量的 ON/OFF cover。一般多输入逻辑、`.gate/.subckt/.latch/.exdc` 等不在首版范围，必须给出明确诊断。DOT 也不泛化为任意图或任意 ABC 逻辑网表；导入入口明确标示“ABC AIG DOT”。

## 2. 当前代码事实与接入原则

| 边界 | 当前事实 | 接入方式 |
| --- | --- | --- |
| 文件入口 | `index.html` 的 Open netlist 接受 `.v/.sv/.txt`；input controller 直接调用 Verilog 设计导入 | 新增 File → Open AIG…，接受 `.dot/.blif`；保留原入口和网表加载服务 |
| 领域注册 | 默认只注册 netlist；DomainFeature 有 import/query/project/search 与 capabilities | 注册独立 AIG feature；通用层通过贡献点和注入能力分派，不增加 AIG 类型判断 |
| 工作区装配 | `moduleWorkspace` 显式调用网表查询、测量、正交布局和 Netlist Scene | 保留网表工作区为既有适配器；增加 AIG 工作区，通过窄的领域工作区入口选择 |
| 流水线与任务 | 已有可注入 view pipeline、JobCoordinator、ArtifactStore 和挂载代际保护 | 复用任务、过期结果隔离和渐进渲染；AIG 自己提供领域阶段 |
| 图形渲染 | 通用 SVG Scene 支持路径和惰性节点/边读取 | AIG Scene 输出受控 SVG primitive；保留曲线，不使用网表 wireRoutes 合并 |
| 调整与几何 | headroom、overrides、Adjust 和校验依赖折线/正交约束 | AIG 走明确的曲线几何契约；首版不进入网表调整路径 |
| 状态与持久化 | 文档、ViewSession 和 Artifact 已有边界，仍存在网表 legacy 投影 | AIG 状态使用文档/会话边界；兼容旧网表存档，避免把 AIG 塞入 `currentModule/cells/nets` |

源码依据：[导入控制器](../../src/app/input_controller.js)、[网表工作区](../../src/app/moduleWorkspace.js)、[领域契约](../../src/contracts/domain_feature.js)、[流水线](../../src/application/view_pipeline.js)、[任务协调](../../src/application/job_coordinator.js)、[通用 Scene](../../src/render/svg_scene_renderer.js)、[正交工作区调整](../../src/app/layoutWorkspace.js)。

推荐数据流：

~~~text
Open AIG
  ├─ ABC DOT 语法解析 → ABC AIG 语义适配 ─┐
  └─ BLIF 语法解析 → AND/NOT 语义还原 ───┤
                                       ↓
                          不可变 AIG + 名称 / 来源映射
                                       ↓
                      规范化、逻辑深度、关键边、扇出
                                       ↓
                          AIG 显示投影 / 稳定 DOT
                                       ↓
                   Graphviz Worker → 节点和样条几何
                                       ↓
                    AIG Scene → 通用 SVG 渲染 / 工作台
~~~

解析器只产出源结构和位置诊断；别名归一化、编号、分析和显示策略位于后续阶段。源模型、规范化模型和布局产物分开保存，保留引用槽位及来源对象。公共层不按 `domainId === "aig"` 添加业务逻辑。

## 3. 实施阶段

| 阶段 | 主要工作 | 完成条件 |
| --- | --- | --- |
| P0：锁定基线 | 记录网表功能、默认 provider、布局几何/诊断与冻结 Simple 证据；建立真实 AIG 成对 fixture 和能力矩阵 | 明确当前通过项与已知失败；后续可区分新回归，不能用已有失败掩盖变化 |
| P1：生产导入与统一模型 | 将研究语义迁移为离线 ES modules；实现两种导入器、校验、规范化、来源映射和稳定身份 | 两种格式得到一致结构；乱序/改名不影响显示图；重名、常量、重复 fanin、重复 AND 身份等边界有测试 |
| P2：Graphviz 离线运行 | 固定 Viz.js / WASM 版本与资源，建立 Worker、取消和几何适配；验证浏览器格式支持和字体 | 断网可用；真实曲线布局成功；超时/取消不阻塞 UI，不回退到网表正交布局 |
| P3：AIG Scene 与分析 | 实现命名节点、曲线命中、极性、关键路径和扇出样式；选择与高亮叠加 | 两格式同图；高亮不改坐标/路径，不误染同源非关键分支 |
| P4：主界面装配 | Open AIG、工作区分派、左右信息栏与画布联动、搜索/导出/会话、能力化菜单与控件 | 从主界面完成真实文件导入到绘制；双侧栏定位、对象检查与跨领域切换正确 |
| P5：回归与发布 | 运行完整适用测试、性能对照、离线 Windows 包和启动检查；更新实际架构文档 | 新功能端到端通过，网表无新增回归，发布包包含全部静态资源与许可证 |

顺序为 P0 → P1 → P2 → P3 → P4 → P5。P2 的浏览器分发可行性检查可在 P1 期间提前开展，但主界面接线必须建立在已通过的真实导入与曲线流水线上。每阶段独立记录验证结果，不把“注册完成”或“单元通过”等同于整项交付。

### P0：保护现有网表行为

- 以实施开始时的当前工作区重新锁定基线，不用历史研究快照替代。
- 网表默认 provider 继续使用 `DEFAULT_LAYOUT_PROVIDER_ID`，记录实际 provider 和显式覆盖；保留既有 fallback 链。
- 代表性样例覆盖普通结构、重汇聚、高扇出、Focused、Compare、手工覆盖和时序标记。记录模型、几何、route status、diagnostics、policy 与交互状态。
- Simple 保持冻结；仅做只读对照，不修改算法、helper、配置或期待值。已有失败单独记录。

### P1：双格式导入与规范化

- DOT：按 ABC AIG 方言解释 shape、label、`dir=back`、`style=dotted`；剔除已确认的标题和不可见布局辅助对象，不误删逻辑节点。
- BLIF：先保留声明与 cover，再还原 AND/NOT；处理 OFF cover、BUF/NOT 链、输出别名和输出反相，不把 NOT 画成额外节点。
- 名称与 ID 分离。PI/PO 显示源名称，内部显示稳定编号；保存源 ID / 名称 / 信号极性到规范化节点和边的映射。搜索支持可读名称及来源标识，不用编号替代名称。
- 扩大原型检查：纯常量设计、零 PI、直通输出、重复 fanin、混合极性、多 PO 共享源、同名冲突、Unicode/特殊字符、无驱动、多驱动、环和超出范围的语法。
- **解决原型的重复 AND 限制**：两个结构相同但身份独立的 AND 必须保留，不能靠静默结构哈希合并获得同图。定义含输入结构、输出使用上下文及对称情况的稳定显示编号/映射规则；补充成对文件与排列不变性测试。若仍有无法规范化的情况，P1 不得标记完成，也不得在产品文档宣称完整支持。
- 不做 rewrite/resyn/balance；规范化不能改变共享关系、节点数量或逻辑功能。重复 NOT/BUF 作为别名消解，原始来源仍可追溯。
- 算法采用迭代拓扑处理和明确的工作预算，避免复制 Python 原型的递归深度限制或引入无界同构搜索。

DOT 语法优先评估用同一 Graphviz 运行时的 `dot_json` 解析，再做独立语义适配；P2 必须确认选定浏览器分发确实支持该格式。若不支持，补齐离线 DOT 语法解析适配，仍须通过同一组 fixture，不能退化为正则抽取连接线。[Graphviz JSON 格式](https://graphviz.org/docs/outputs/json/)

### P2：Graphviz 与曲线几何

- 使用固定版本、随包分发的 Viz.js / Graphviz WASM，运行时无 CDN、无外部进程、无 Python/ABC 安装要求。按需初始化，不让网表首屏等待 Graphviz。
- 在实施时记录实际版本、文件清单、哈希、许可证、WASM / 字体资源路径、冷启动时间与包体；原生 Graphviz 2.43.0 的研究图只作风格参考，不假设 WASM 版本像素一致。
- 优先取布局 JSON 的形状/文字/路径绘图信息，转换为受控几何与 Scene；不直接挂载用户 DOT 生成的任意 SVG，不保留外部链接、脚本、图片等无关属性。
- 明确节点中心/边界、曲线控制点、箭头、标签位置、坐标方向、单位与包围框。曲线不装进语义不明的折线 `edge.points`，不经过现有正交 validator、wireRoutes 或 Adjust。
- Worker 的作业生命周期接入现有取消与修订保护。WASM 同步调用无法仅靠 AbortSignal 中断时，终止并重建对应 Worker；旧结果不得回写新文档。
- Cache key 纳入文档修订、规范化版本、显示图、Graphviz 版本、字体及布局设置；高亮和当前选区不进入布局缓存键。
- Worker 入口与应用模块保持可静态检查；第三方资源经固定清单装载。若需要新的资源边界，先给出窄范围契约和检查，不能用动态路径绕过架构门禁或全局放宽依赖规则。

### P3：图形与高亮

- PI/PO 名称完整展示；长名称采用一致的测量与节点扩展规则，同一配置下两格式必须得到相同尺寸。内部节点保持紧凑编号。
- AND 按逻辑深度分层、PI 在底层、PO 共同顶层；未使用的常量默认不展示，仍保留源信息。
- 反相虚线逐逻辑边保留，包括输出边和重复 fanin；平行边与同源正反相边的身份不能被绘制合并丢失。
- 关键路径按单位 AND 延迟计算所有最长 PI/常量至 PO 路径上的节点与边，明确是“逻辑关键路径”，不冒充真实器件时序。单独判定关键边，不能仅凭两端都是关键节点染色。
- 扇出按完整规范化 AIG 的引用槽位计数，包含 PO；默认高亮阈值 ≥ 2，支持调整，Inspector 显示具体数值。此处指扇出数量高亮，扇出锥裁剪不作为首版交付。
- 两种高亮独立开关：关键节点红色填充、关键边红色描边、高扇出橙色边框；虚线始终表示反相。选中/搜索使用独立外框或光晕，避免覆盖既有语义。
- 高亮只更新展示状态和必要 DOM 样式，不重新解析、分析或布局。UI 图例、Inspector 文字和线宽帮助区分状态，导出 SVG 保留当前样式。
- 曲线使用更宽的透明命中路径对应同一 edge ID；显示路径与命中路径保持一致，继续支持可取消的渐进挂载。

### P4：主界面与状态

- File 新增 **Open AIG…**；保留 Open netlist… 原入口。AIG 导入错误显示文件名、位置或源对象、原因和格式范围。
- 新文件先在独立候选任务内解析、分析和准备首个 Scene；成功后提交文档/会话。AIG 导入或布局失败时保留当前可用视图，不触发网表的 fallback。
- Navigator 与 Inspector 都纳入首版交付，内容与联动按下方两侧信息栏方案实施；沿用现有面板容器、停靠/抽屉、开关与调宽机制。
- AIG 布局选择显示 Graphviz；网表继续显示原 provider 列表。AIG 控制条加入关键路径和扇出开关/阈值；门级 Timing、Liberty、Cell Config、Adjust、Compare 等按能力隐藏或禁用，命令入口同样检查能力。
- 会话包含格式、源文本/身份、领域 ID、规范化/存档版本、选区、视口与高亮状态；WASM 实例、Worker、Scene 闭包和几何缓存留在运行时产物层。
- 切换 AIG / 网表时取消旧任务并隔离历史、缓存、覆盖、时序与选择。恢复旧网表存档继续沿用兼容解码；AIG 存档不能进入网表解码器。源对象找不到时给出可解释的恢复结果，不误选同名对象。
- 主入口只装配服务与控制器，不放解析、分析、任务调度或新的大段 UI 分支；如 main 接线需要空间，先提取完整职责并降低现有行数上限。

### P4 补充：左右信息栏与画布联动

**左侧 Navigator 负责全图概况和找到对象。** AIG 使用 `Design / Objects` 页签；当前输入是平坦图，不显示网表专用 Hierarchy 树。切回网表恢复既有 `Hierarchy / Design` 内容。

| 左侧内容 | 展示与操作 |
| --- | --- |
| Design 概况 | 文件/设计名称、输入格式；PI、AND、PO、逻辑边、反相边数量；最大逻辑深度、关键节点/边数量、高扇出节点数量。统计读取完整 AIG 分析结果 |
| Objects 对象列表 | 支持输入、输出、AND、常量的类型筛选；PI/PO 显示原名，内部节点显示稳定编号，可检索来源名称/ID |
| 分析筛选与排序 | 可筛选关键节点、高扇出节点；按名称、逻辑深度或扇出排序。高扇出筛选与工具栏的阈值一致，复用已有分析索引 |
| 定位 | 点击条目选中并居中定位画布节点，同时更新右侧详情；标记当前选择。列表筛选只改变侧栏内容，不裁剪图、不触发布局 |

全局 Search 与 Objects 筛选复用同一份 AIG 搜索索引及对象引用，不另造名称匹配规则。默认优先展示输入/输出，避免初次打开即铺满大量内部节点；通过类型筛选访问全部节点。原始名称完整可查看、复制，不用截断文字作为匹配键。

**右侧 Inspector 负责解释当前对象和沿连接追踪。** 顶部固定显示完整名称或内部显示编号、类型、当前来源文件，并提供复制与 `Zoom to selection`。页签使用 `Connections / Analysis / Source`；AIG 不显示网表专用 `Timing / Adjust` 页签，切回网表恢复原内容。

| 右侧内容 | 展示与操作 |
| --- | --- |
| 节点 Connections | 直接 fanin / fanout 列表；每条引用独立显示来源、目标、输入槽位、正相/反相及是否属于关键路径。重复 fanin 和正反相混合扇出不能合并成一个含糊条目 |
| 边 Connections | 点击曲线后展示该逻辑边的源、目标、目标输入槽位、极性及关键性；选中一条边不能误选同源的全部分支 |
| Analysis | 选中节点的逻辑深度、扇出引用数、关键性及当前高扇出阈值命中情况；说明扇出包含 PO、关键路径使用单位 AND 深度。边对象显示适用的分析项 |
| Source | 显示规范化对象与原 DOT 节点 ID / BLIF 信号名、别名和极性的映射；显示可获得的源码位置。一个对象对应多个源别名时保留全部对应关系 |
| 连接跳转 | 点击邻接节点定位并选中该节点；点击连接条目选中具体逻辑边。同步画布与左侧选择，不改动连接关系或几何 |

全图关键路径开关、扇出开关和阈值仍由工具栏统一控制；右侧解释当前对象的状态，避免出现两套独立高亮配置。未选择对象时提示从画布或左侧选择，不展示上一份文档的残留详情。

联动与性能约束：

- 三处共享同一会话选区与对象引用，通过已有命令/导航边界更新。画布选中后，左侧标记对应条目，右侧切换详情；若对象被列表筛选排除，提示“当前选择不在筛选结果中”并提供显示入口，不擅自清空筛选。
- 左侧对象列表、右侧高扇出连接采用分页或有界列表，沿用现有列表呈现约定。选择/悬停不扫描整图、重新分析或重新布局；连接索引由模型/分析阶段准备。
- 面板开关与调宽保持当前画布中心和缩放比例，不触发 Graphviz、不新增布局历史。宽屏停靠、窄屏抽屉及偏好存储沿用现有响应式规范，不强制所有窗口同时展开两栏。
- 页签、筛选、滚动位置与选中对象在 AIG 文档切换时正确恢复或重置；面板宽度/显隐等界面偏好继续独立存储。网表与 AIG 的详情内容、页签和命令不能串用。

两侧内容由 AIG 查询和面板贡献提供，通用面板壳只负责装配与交互基础；不复制网表 Inspector 的 cell/pin/net 业务，也不向公共控制器加入 AIG 专用算法。

## 4. 拟新增/调整的职责位置

下表是职责划分，具体文件名在实施时随现有边界确认，不以新增大量框架文件作为完成标准。

| 位置 | 职责 |
| --- | --- |
| `src/domains/aig/` | ABC DOT / BLIF 源结构适配、统一模型与规范化、分析、查询/搜索、显示投影、AIG Scene、feature |
| `src/contracts/` | 必要的曲线几何、工作区能力和作业结果契约；不包含 AIG 算法 |
| `src/layout/` | 领域中性的 Graphviz 布局几何适配，运行时通过窄接口注入 |

| `src/application/` | 领域中性的文件导入用例、工作区选择/提交与任务协调，使用已有文档和会话设施 |

保持 `parser → model → analysis → layout → Scene → UI` 的方向。共享契约的增量变更须在 Netlist 适配器上证明行为不变，不借此重构冻结 Simple。

## 5. 验收矩阵

| 验收项 | 必须通过的证据 |

| 双格式语义 | 成对 fixture 的规范化结构、PI/PO 名称、极性、共享关系、分析结果一致；小图全真值、大图结构检查及外部工具抽样验证 |

| 图形风格 | 与带名称研究基线并排人工检查；无节点/标签遮挡、反相与箭头丢失、非预期正交化 |

| 左右栏联动 | 左侧名称/类型/分析筛选 → 定位画布 → 右侧详情；画布点节点/曲线 → 两栏同步；连接跳转准确到节点或逻辑边，重复 fanin 与混合极性可区分 |
| 面板状态与性能 | 长名称可查看/复制，大列表有界；筛选与面板开关/调宽不触发布局且保持视口；宽窄屏可用，AIG↔网表切换后页签、选择和内容不串用 |
| 生命周期 | 慢任务中切换文件、重复导入、取消、失败、AIG↔网表、从网表 Compare 打开 AIG、刷新恢复；旧结果和旧状态不串入新文档 |
| 网表行为 | `npm test`、`npm run test:architecture`、布局确定性与 fixture 不变量、workbench/UI e2e；新旧代表性网表模型、几何、状态/诊断对照无变化 |
| 综合设计回归 | `MAPPED_CASE_NO_COLLAPSE=1 npm run test:mapped-cases`；默认 provider 来自 `DEFAULT_LAYOUT_PROVIDER_ID`，报告实际 provider，保留显式覆盖与已有失败证据 |
| 性能 | `npm run benchmark` 及必要的 workspace/interaction 对照；测 AIG 冷/热加载、布局、首帧、峰值内存、取消与高亮切换，包含宽层、长链、重汇聚和高扇出样例 |
| 离线发布 | `npm run release:windows`，离线启动、Worker/WASM/字体加载、两格式打开和网表回归；保留 ELK 许可证并加入 Graphviz/Viz.js 相应许可证。其他启动路径做资源可达性检查 |

构建、依赖准备、测试与大临时产物优先在 `mfs-remote` 执行，用户项目放在 `/home/wzh/my_code/netlistGraphBuilder`。Windows 发布构建及必须的本机离线 GUI 冒烟检查在 Windows 执行并记录原因；仅将需要审阅的报告和图片带回本地。
