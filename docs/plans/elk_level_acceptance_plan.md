## 1. 目标与适用范围

把“接近 ELK”转为可复现、可审查的布局与布线质量结论，再决定是否替换当前 Native 实现。
目标是工程师能够清楚识别独立树、共享 DAG、信号方向、干线和分支；不是复制 ELK 的绝对坐标。

范围保持为离线、浏览器原生 ES modules、单 module 平面画布、左到右布局、固定西/东端口，
包含长边、高扇出物理 net、反馈边、自环和完整非连通分量。保持 parser→IR→分析→layout→render→UI 边界。

本计划是 [完整重实现计划](elk-native-reimplementation-plan.md) 的验收收口细化，
不重新启动 ER-00～ER-09，也不重新写一套算法。已有源码依据与契约继续有效：

- [ELK 源码审计](../research/elk-layered-source-audit-2026-09-24.md)。
- [P0～P5 相位契约](../design/elk-native-phase-contracts.md)。
- [分层语料说明](../experiments/elk-parity-corpus.md)及 [18-case manifest](../../tests/fixtures/elk_parity/manifest.json)。
- [真实执行记录](../progress/work-log.md)。

### 当前明确不做

- 性能优化继续暂停，包含 dp020 专项优化、新 profiling 和 benchmark 工作。
- 不提高 45 秒 worker 超时，不减少 47 个全图，不恢复 collapse，不跳过严格 validator。
- 不迁移 C++/WebAssembly，不更换 ELK 版本，不改 Simple 默认 provider。
- 不引入实例名、fixture ID、绝对坐标或固定树间距规则；不增加 P4 之后的连通树打包/挪动。
- 不切换未通过门禁的候选，不先删除旧算法，不用发布包掩盖实验状态。

质量验证所需的正常测试与耗时记录不等于重新开启性能优化。若任务开始以降低耗时或内存为目标，
即越过当前暂停边界，必须先取得用户新指令。

## 4. Q01／Q02：样本与视觉协议

### 样本策略

复用已有 manifest，不临时挑“好看的图”作为验收集。优先顺序：

1. 三个用户场景：SOP015 `_5426_`、EQ012 `_1471_`、EQ012 `clk`。
2. 合成机制图：链、菱形、平衡树、不平衡共享叶、重汇合长边、多端口 fanout、反馈/自环、
   外部端口、非连通分量、不等高度密集端口，以及 bootstrap smoke。
3. 三个固定 mapped 分层样本：sop001、eq006、dp002。大图使用整体概览和预先登记的局部窗口；
   不用局部图通过替代全图正确性。
4. `p5_critical_split_001` 是白盒机制 probe，不伪装成完整图的视觉验收。

自环辅助 oracle 与正式 manifest 分开注明来源。若需新增场景，先登记机制缺口、输入和选择理由，
冻结后再运行；不能看到失败后删样本或改变其归属。输入未物化时先补 test-only 生成器及稳定 ID，
不得在生产算法中加入场景生成或识别代码。

### 每次对照必须固定

- 同一 source/query/display graph，保存源文件及 provider 输入哈希。
- 同一节点测量、端口位置、hub/alias/Focused/presentation 选项；不使用 collapse 或手动 override。
- 同一次运行的 vendored elkjs 0.11.1 作为产品参考；相位语义使用既定 pinned Java oracle，
  不把两种参考的坐标、默认值或指标混用。
- 候选源码文件哈希、contract/package、Node/浏览器版本、随机种子及完整配置。
- 两侧相同画布尺寸、viewBox 尺寸与 zoom。整体采用覆盖两图的公共坐标窗口，不分别 Fit。
- 局部以同一 canonical 对象为锚，各取同尺寸窗口；只做统一平移/裁剪，不重排或单独拉伸。
- 完成态 label、bridge、junction、hit area 保留；不得只用隐藏标签的低细节预览作证。

每个报告同时包含整体、关键局部、硬违规分类、拓扑、逻辑/物理质量指标及审查结论。
被裁掉的分支要在整体图里可追溯；裁剪工具只用于显示，不能把裁剪图送给 validator 或当作新布局。

## 5. Q03／Q04：先归因，后改代码

沿 P0 输入→P1 方向→P2 排名→proper/dummy→P3 节点/端口顺序→P4 BK→P5 槽位/几何
→恢复→公共物理线/Scene 顺序查找首个可解释分歧。后阶段不能偷偷补前阶段缺失信息。

每个缺陷卡记录：现象、固定输入、首个分歧、源码依据、当前适配规则、影响范围、假设、
预计改善指标、反证条件、最小测试、对照实验、结果与结论。一次只验证一个主要假设。

首批只登记以下三个假设，不预先指定修复答案：

| 假设 | 对照与证伪方式 | 成功条件 |
| --- | --- | --- |
| H01：SOP015 输出偏低首先来自排名／排序 | 对齐端口输入、排名与完整 layer order；若上游结构一致，则转查 BK，不改排名凑图 | 找到有证据的 owning phase，而非猜测或固定坐标调整 |
| H02：长连线来自 BK alignment／候选选择差异 | 固定同一 proper graph 与顺序，对照四候选、root/align/innerShift/class shifts；若选择符合约定，记录合法差异 | 只修已证明的缺项；短线改善不破坏 spacing 或独立树辨识 |
| H03：视觉线束差异来自 P5 或公共线投影 | 固定 P4 输出，对照 segment/dependency/split/slot/width，再核对 logical→physical→Scene | 定位算法或投影边界；不挪 P4 节点、不改硬校验来减少线 |

合法的 deterministic tie 差异不要求逐像素相等。超出已记录适配范围的差异，必须先审查相位契约；
如需契约变更，版本化记录并重跑影响范围。不能以“最后更好看”为由掩盖相位语义错误。

## 6. 验收门禁与结论口径

### 不可妥协的硬门禁

- 零缺线、零错误端口/方向、零节点穿越、零不同 net 共线重叠及其他共享硬违规。
- logical lineage 完整；物理 net 连接不丢分支、不错误合并，无意外 forest、cycle 或 fallback。
- 输入不被修改；节点/边/parser 顺序排列不影响确定性结果；中断/失败不提交半成品。
- 固定 47 个 full-node case、原 45 秒 worker、严格 validator；超时算失败，参考 ELK 的违规不能
  为候选豁免。当前 dp020 失败继续保留。

### 软质量与视觉门禁

保留重实现计划的 SOP015 门禁：列数至少 10（原例外条件不变），逻辑/物理交叉分别不超过
`1.5 × 同次 ELK + 10`，逻辑总长度不超过 `1.5 × 同次 ELK`；`_5404_` 输入树需在同视口清楚可辨。

EQ1471 保留四分支、两个共享组，fragmentation 与同次 ELK 比较而不是强求 ELK 自身不满足的零值。
共享物理干线的连接与硬合法性另行检查，不能被 fragmentation 指标代替。

扩展样本逐项记录：层数/顺序、逻辑与物理交叉、逻辑与唯一物理线长度、折点、bounds/面积、
空白分布、标签可见性及分支追踪难度。逻辑长度不能替代唯一物理长度；少折点不能抵消断线或混树。

新增场景的数值上限在 Q01 登记为“拟定标准”，基于对应机制和既有规则在修改算法前审查冻结；
本文件不自动修改现有测试阈值。未冻结口径的场景只报观察，不报“验收通过”。
结果逐场景判定；平均数、挑选截图或总交叉降低不得掩盖任何未解释的明显可读性退步。

用户可以因绘图难读拒绝数值门禁已经通过的结果；拒绝后回 Q03，不继续微调常数。

### 何时可以说“达到 ELK 水平”

只有在约定范围内的机制样本与 mapped 分层样本全部取得可复现质量证据、相位差异均解释或修复、
硬门禁全部通过（含正式 47/47）、用户视觉接受且产品集成/离线验证完成后，才能作范围限定的结论：
“在已声明的平面网表布局范围和验收语料上达到约定的 ELK 可读性水平”。
不能宣称所有图都更好、全算法最优或全面等价 ELK。默认 provider 提升仍需独立产品决定。
