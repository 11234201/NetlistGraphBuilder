# 前端大图交互性能改进计划

更新日期：2026-11-17。状态：P1–P3 已实现并验证；P4 追加 4K 全图手势调度、平移恢复与接管修复，性能仍有未通过项；P5 已完成有界试验，未启用产品裁剪。执行结果与未完成项见第 8 节，最新对照见 8.6。

目标是改善 Netlist 与 AIG 大图下的缩放、空白处拖动平移和节点选择响应。实施顺序为：建立可靠的交互基线，减少共享画布的重复尺寸读取，调整 Netlist 属性面板更新时序，补齐 AIG 手势期间的细节简化，再进行完整回归。按视口裁剪只作为后续条件项。

本计划承接 [阶段 8 计划](../STAGE_8_PLAN.md) 的交互性能工作。执行约束以 [AGENTS.md](../../AGENTS.md)、[领域技能](../skills/netlist-schematic/SKILL.md)、[架构设计](../ARCHITECTURE.md) 和 [交互设计](../DESIGN_SPEC.md) 为准。

## 1 用户问题与处理顺序

用户感受到的是图变大后的操作反应慢。为了避免把不同原因混在一起，按下面四类操作分别测量和验收。

| 操作 | 用户应看到的结果 | 本轮处理重点 |
| --- | --- | --- |
| 滚轮缩放 | 图跟随滚轮变化，鼠标所在位置稳定 | 减少变换后的重复尺寸读取和 SVG 排版绘制成本 |
| 空白处拖动 | 图随鼠标移动，松手时不明显停顿 | 保持轻量预览，控制手势开始和结束时的细节切换成本 |
| 选择节点或线网 | 高亮及时出现，属性栏显示正确对象 | Netlist 属性栏更新与尺寸测量分开；保留 AIG 已有的邻接索引 |
| Adjust 中拖动节点 | 拖动预览顺畅，释放后正确重布线 | 先补测预览与释放后的提交；与普通平移分别记账 |

前三项是本轮主要交付范围。Adjust 的释放后重布线尚未完成本次诊断，不能把它直接归因于同一热点，也不预先承诺修改路由算法。

## 2 当前证据与限制

诊断快照对应 `48ea0ed`，关键热点文件与该提交一致。环境为 `mfs-remote` 上的 Linux 无头 Chrome `146.0.7680.164`，窗口为 1440×900。Netlist 使用默认 `native-layered`，Whole 全节点且不折叠；AIG 使用 Graphviz。

| 受控样本 | 已观察到的结果 | 支持的结论 |
| --- | --- | --- |
| Netlist 4098 节点 | mount 下有 57358 个元素；连续选择 8 次累计浏览器 Layout 3261ms | 属性面板同步布局是明显热点 |
| Netlist 4098 节点 | 30 次滚轮事件累计 Layout 1027ms；尺寸观察回调调用链约 862ms | 变换后的同步尺寸读取增加缩放成本 |
| AIG 2050 节点 | mount 下有 33808 个元素；30 次滚轮事件累计 Layout 326ms | 共享尺寸观察路径同样影响 AIG |
| 独立 timeline 记录 | Netlist 1026 节点缩放累计 Paint 623ms；AIG 2050 节点缩放累计 Paint 592ms | 仅减少 JavaScript 运算不能解决全部绘制成本 |
| 普通选择、缩放和平移 | 新布局 Worker 请求为 0；保存调用未成为主要热点 | 优先处理 UI 和渲染边界 |
| AIG 普通低度节点选择 | 本次样本未发现超过 50ms 的主线程任务 | 不把 Netlist 属性面板问题套用到 AIG |

这里的 Layout 是浏览器为页面和 SVG 计算尺寸位置的工作，与 AnchorLayered 或 Graphviz 的自动图布局不同。表中累计时间对应一组操作，不是一次点击延迟；CPU profile 的调用链时间与浏览器阶段时间不能相加。

## 3 保持的产品与架构边界

- 覆盖 Netlist Single、Netlist Compare 和 AIG Single 的 Standard / ABC 样式。AIG Compare 仍属于 [AIG 后续路线](aig_followup_roadmap.md)，本轮不新增该功能。
- Simple 继续遵守 [冻结基线](simple_layout_freeze_baseline.md)。不改其算法、策略、默认值、诊断、路由状态或几何，不刷新预期值隐藏变化。
- 不改变 parser、IR、自动布局产物和手工覆盖的归属；不改变节点坐标、引脚、导线路径、canonical ID 或显示名称。
- 不引入 group collapse、前端框架、打包器或联网运行依赖。性能用例使用 Whole、Search-first 或 Focused。
- 共享视口与手势行为在 `ui/` 的共同边界实现；领域展示由 `domains/` 提供。通用层不增加 AIG / Netlist 条件分支。
- `src/app/main.js` 保持组合入口。需要的调度由所属控制器或 `application/` 承担，不扩大全局状态端口。
- 高频手势每帧只做轻量预览，禁止重新布局、重建全图 SVG 或逐事件持久化。昂贵提交保留在手势结束后的明确边界。
- 完成态保留完整几何、语义、标签和点击区域；临时细节简化必须恢复。静态 SVG 导出不能带有手势中的隐藏状态。

### P0 固化可比较的交互基线

**目的：明确一次操作花了多少时间、结果是否正确，并让修改前后能够公平比较。**

1. 将临时诊断中的有效部分整理为测试代码，拟新增 `tests/e2e/frontend_interaction_performance.mjs`，复用现有 `browser_test_session.mjs` 的启动、超时和清理机制。保留环境变量指定测试用浏览器与 Playwright，产品不新增依赖。
2. 为每个样本记录源内容摘要、节点与边数、DOM 元素数、provider、视图模式、AIG 样式、视口、面板状态及浏览器版本。Netlist provider 从 `DEFAULT_LAYOUT_PROVIDER_ID` 获取，保留显式覆盖。
3. 分离无 profiler 的响应时间测量和带 profiler / trace 的归因测量。trace 用于找原因，不与普通测量混算提速比例。
4. 正式操作使用浏览器鼠标、滚轮和键盘输入。先确认目标在屏幕内可点击，记录事件是否命中预定节点、选择是否改变、视口是否移动。合成事件只留作单独标记的压力探针。
5. 每组至少 5 轮，先预热，再交替运行基线与候选快照。选择用例每轮不少于 20 次；连续平移和缩放各覆盖至少 3 秒，并单独记录手势起始、持续、结束恢复三个区间。
6. 区分高亮出现与属性详情就绪时间。通过浏览器事件时刻和后续帧观察给出可复测代理指标；不能把双 `requestAnimationFrame` 描述为精确像素呈现时间。需要时用 trace 和截图核对实际可见结果。
7. 报告 P50 / P95、手势期间帧间隔、超过 50ms 的主线程任务、Layout / Style / Paint / 图层耗时、布局请求数、完整 SVG 替换数和保存次数。Playwright 调用往返时间单列，不充当应用响应时间。
8. 新脚本一旦出现目标未命中、页面异常、加载失败或超时，立即把该样本标为失败。不能继续操作旧图后记成性能成功。

**样本分层：**

| 类别 | 主测样本 | 补充覆盖 |
| --- | --- | --- |
| Netlist 合成图 | 约 1K、4K 节点，保留原 BUF 链用于纵向对照 | 宽层、扇出、交叉密集、较长名称 |
| Netlist 真实图 | 从现有 47 个 mapped fixture 中选中等、较大和高连线密度代表 | 记录选择依据与规模；Whole 和 Focused 分开 |
| Netlist Compare | 两侧中等图、一大一小图 | 同步和独立视口、左右与上下排列 |
| AIG | 约 500、2K 节点，Standard 与 ABC | 宽层、长链、汇合、高扇出、反相边和转义名称 |
| 轻量场景 | 内置样例、空选择、Search-first | 防止为大图优化牺牲日常小图 |

AIG 高扇出节点选择单列：邻居高亮的工作量本来就与实际相邻边数有关，不与普通低度节点共用固定更新数量上限。

**完成条件：**同一快照重复运行结果方向稳定；每组的正确性断言通过；正式基线不含探针错误或旧图误测。已有初诊中的错误选择器样本和不正确等待条件样本不进入基线。

### P1 减少共享画布重复尺寸读取

**用户收益：滚轮缩放和画布平移减少多余的同步排版。**

主要边界为 [画布尺寸控制器](../../src/ui/canvas_resize_controller.js) 和 [共享视口桥接](../../src/app/workbench_viewport_bridge.js)；必要时调整使用它们的窄接口。

1. 将缓存中的三类信息分开维护：SVG / content 身份与 viewBox、容器尺寸与位置、权威视口及尚未提交的预览视口。
2. `transform` 的 MutationObserver 只同步视口变化、外部重置与预览归属，不在每次变换后调用 `getBoundingClientRect()`。
3. 由 ResizeObserver、SVG 替换和显式尺寸变更更新尺寸记录。初始化或缓存无效时允许受控读取；稳定尺寸下的高频路径复用缓存。
4. 保留计算 resize 增量所需的旧尺寸，先使用旧值完成阅读位置补偿，再推进新基线。不能因更新缓存过早而丢失窗口或面板变化量。
5. 区分外框大小与屏幕原点。ResizeObserver 提供尺寸，不一定提供最新屏幕位置；手势起始、容器位置变化和显式重置时按需刷新坐标，不能用缓存宽高替代全部鼠标坐标转换。
6. 保留 same-value Fit、隐藏后重新显示、SVG 替换、Compare 双侧同步、AIG 预览提交，以及 resize 未结算时被滚轮或平移接管的语义。旧观察回调不能覆盖新视口。
7. 保留取消与销毁处理，确保延迟回调不作用于已关闭文档或替换后的画布。

**验证重点：**扩展现有 `canvas-resize-controller.test.js`、`workbench-viewport-bridge.test.js`、`domain-canvas-controller.test.js`，并跑真实浏览器交错手势。断言尺寸未变时，transform 观察回调不发起同步几何读取；真实 resize 仍正确补偿中心和物理阅读比例。

**退出条件：**同步测量调用链按设计消除，主测组缩放 Layout 累计耗时以降低至少 40% 为目标，且手势响应指标改善。若成本转移到另一同步读取，继续定位，不以删除一个调用为完成标志。

### P2 调整 Netlist 属性面板更新时序

**用户收益：选中对象后，高亮更快出现，右侧详情不再拖累整个操作。**

主要边界为 [属性页签控制器](../../src/ui/inspector_tabs_controller.js)、[属性呈现适配器](../../src/app/inspector_controller.js) 及已有选择控制器。Single 与 Compare 共享这一实现。

1. 将立即可完成的选区更新与详情 DOM 提交分开。选区身份及时进入现有命令边界，随后合并同一轮中的重复详情刷新。
2. MutationObserver 负责识别内容和选区变化，不在刚替换 DOM 后立即读取摘要尺寸。优先消费 ResizeObserver 的 box 数据；无该能力时采用有缓存的延后测量回退。
3. 对摘要测量、页签结构、可见面板和滚动恢复分别管理失效。页签集合未变时复用现有导航节点，避免无条件 `innerHTML` 重建；也要识别整个详情内容被替换后的新节点。
4. 保留 sticky 摘要和标签页。尺寸回调核对对象身份与 DOM 代际，只在有效高度变化时更新 CSS 变量，避免观察器反馈循环。
5. 保持同一对象的当前页签与滚动位置；切换到不同对象按现有规则重置。继续支持名称复制、键盘导航、焦点保持、Timing / Adjust 控件、Hierarchy 和分页。
6. 若详情采用异步提交，为每次选择记录代际。快速点击 A、B、C 时，最终详情必须属于 C；导出、复制和快捷操作不能误用尚未更新的旧详情。不能只把代码放进 Promise 或一层 rAF 就视为优化完成。
7. 再次采样仍有查询热点时，才考虑在领域查询边界复用索引。不得未经测量就改写逻辑锥分析，或用无界的每节点详情缓存换速度。

**验证重点：**现有 `inspector-tabs-controller.test.js`、`inspector-panel.test.js`、`selection-navigation.test.js` 和 UI workbench 浏览器测试。补充快速连续选择、过期 ResizeObserver 回调、面板关闭后选择再打开、长名称换行、Compare 两侧来源和 sticky 高度变化。

**退出条件：**主测组选择操作的累计 Layout 耗时以降低至少 50% 为目标；高亮和详情就绪分别满足第 5 节目标；属性内容、滚动与焦点语义正确。若测量成本只是移到 `scrollTop` 或其他读写位置，继续处理完整刷新链路。

### P3 补齐 AIG 手势期间细节简化

**用户收益：大 AIG 平移、缩放时减少浏览器需要处理的文字和装饰细节，停下后恢复完整图。**

主要边界为 [AIG Scene](../../src/domains/aig/aig_scene.js)、[领域画布控制器](../../src/ui/domain_canvas_controller.js)、共享手势状态及 `styles.css`。

1. 为 AIG 可简化文字和装饰提供明确的展示角色，复用共享手势状态；不在通用渲染器里按领域 ID 分支。
2. 先只做手势期间的临时细节策略。第一候选是暂时隐藏非选中对象的文字与非必要装饰，保留拓扑线、方向、反相语义、关键分析颜色和选中对象反馈。
3. 分别测量 `display`、`visibility` 等可行方式对 Style、Layout、Paint 和完成恢复的成本。以真实结果选择实现，不假设某个 CSS 属性必然更快。
4. 不无条件关闭全部命中区域。只有已捕获的空白平移等明确手势才可临时减轻相关命中工作；保留节点选择、键盘焦点和手势中断行为。
5. 覆盖正常结束、取消、失去 pointer capture、切换文档、切换 Standard / ABC、画布离开和销毁。所有退出路径恢复细节并取消旧定时器。
6. 静态 SVG 导出从完整 Scene 生成，不复制当前临时隐藏状态。AIG 节点与边的几何、名称、箭头、反相、邻接高亮、关键路径和高扇出含义保持一致。
7. 检查 Netlist 既有手势细节切换的开始与恢复成本。只有证据表明其属于主要残留热点，才在同一展示边界优化；不改 Simple 输出或布局策略。

**验证重点：**AIG Standard / ABC 的真实浏览器平移、缩放、选择和取消；手势前后标签与命中区域完整性；关键路径、反相和高扇出样例；离线导出。复用 `aig-interactions-e2e.mjs`、`aig_views_e2e.mjs` 与 AIG 工作台测试。

**退出条件：**主测大 AIG 手势期间的浏览器渲染阶段成本与慢帧指标以降低至少 30% 为目标，恢复阶段不出现更大的停顿，完成态正确。P3 不声称降低最终 DOM 数量；该问题只有进入 P5 后才处理。

### P4 综合回归与 Windows 验收

**用户收益：确认改进能在实际入口使用，并且没有引入视口跳动、详情错位或显示缺失。**

1. 在与 P0 相同的环境和样本上复测，报告各阶段独立收益及最终叠加结果。保持输入、provider、视口、显示策略一致；P3 的手势细节差异需明确记录。
2. Netlist 覆盖 Whole / Focused / Search-first、Single / Compare、同步与独立视口、窗口及面板 resize、Fit、搜索定位、历史恢复、Session / Golden 恢复。
3. AIG 覆盖 Standard / ABC、普通与高扇出选择、邻居和分析高亮、样式切换时取消、离线导出及存档恢复。
4. Adjust 将按下选中、预览、释放后重布线、完整渲染分别计时。若释放后计算仍慢，作为独立后续项记录具体阶段；不以本次 UI 改动为由扩展到路由算法优化。
5. 校验多次载入、切换和重复手势后没有持续增加的 observer、事件监听、旧 DOM 引用或定时器。记录稳定后的内存趋势，不把单次 GC 波动当作泄漏。
6. 执行第 6 节对应验证矩阵。Windows 做有界的离线包与交互 smoke，确认文字恢复、焦点、鼠标缩放和平移正常；完整压力测试与大日志仍留在远端。

**退出条件：**功能硬门槛全部通过，性能目标达到或逐项列明剩余差距，既有失败单独记录。未达到的目标保持未完成，不用缩小输入、删除 mapped 用例或放宽正确性断言掩盖。

### P5 条件项 视口渲染方案

P4 后若尺寸与面板热点已消除，而大图交互仍主要受 SVG 规模限制，才进入这一阶段。若 P1–P3 已满足目标，停止扩大范围，保留 P5 为后续。

这一阶段先形成设计和试验，不直接将持久裁剪设为默认。当前项目要求完成态恢复完整显示；长期减少已挂载对象会扩展现有渲染契约，需要先明确逻辑完整 Scene 与可见 DOM 的关系，并同步相关设计文档。

设计需解决：

- 全量逻辑数据、布局几何、搜索和导出仍然可用；可见性不改变图本身。
- 使用有界空间索引及视口外预留区域，避免每个 pointer / wheel 事件扫描全图或重建 SVG。
- 快速平移时不出现大面积空白，跨视口导线、箭头、标签、桥接、曲线与命中区域完整。
- 屏幕外的搜索结果、选中对象和键盘目标能可靠显现；AIG 的 `objectElements` 等引用不能因卸载而失效。
- 多批挂载可取消，旧批次不能写入新图，稳定顺序和 SVG 导出结果不依赖访问视口的顺序。
- 与现有“高频手势只更新轻量预览”的边界兼容；不能把新增 DOM 工作直接塞进 pointer handler。

先对一个代表场景验证正确性、帧时间和内存收益，再决定分块挂载、可见区域管理或其他方案。Canvas / WebGL 属于更大技术变更，不作为本计划的默认选项。

## 5 性能目标与判定方式

下面是实施目标，不是已有测量结论。P0 将参考机器、样本和动作固定后使用；不能在看到候选结果后换输入或调整阈值。

| 指标 | 主测参考组目标 | 大图压力组目标 |
| --- | --- | --- |
| 选择后的可见反馈代理时间 | P95 ≤ 100ms | 较基线降低至少 30%，单列高扇出 |
| 属性详情就绪代理时间 | P95 ≤ 200ms，内容身份正确 | 较基线降低至少 30% |
| 连续平移与缩放帧间隔 | P95 ≤ 34ms | 慢帧与总阻塞成本较基线降低至少 30% |
| 手势结束后完整细节恢复 | P95 ≤ 100ms | 单独记录，不把停顿转移到结束时 |
| 小图回归 | 中位数增加量 ≤ `max(基线中位数 × 10%, 5ms)` | 不适用 |

主测参考组以约 1K 节点 Netlist 和约 500 节点 AIG 为起点，并加入规模相近的真实或代表性图；压力组以约 4K 节点 Netlist 和约 2K 节点 AIG 为起点。拓扑差异较大的图分组报告，不用混合平均值隐藏坏例。

性能比较使用同机交替测量、每轮统计值的中位数和离散范围。若噪声超过待比较收益，先说明结果未定并改善测量条件，不直接宣布优化成功。浏览器阶段可能存在嵌套，不能把所有 trace 事件耗时简单相加。

慢帧按手势活动窗口中超过 34ms 的帧间隔计数，并同时报告其比例；总阻塞成本按该窗口内每个长任务的 `max(任务时长 − 50ms, 0)` 求和。操作后的空闲等待不计入手势帧统计，恢复阶段单独统计。

所有阶段的功能硬门槛包括：普通选择 / 平移 / 缩放不新增自动布局请求、不替换全图 SVG；高频事件不写入持久化；视口不被过期回调覆盖；选区与详情一致；完成态和导出完整；默认 provider 与 Simple 冻结契约保持不变。

### 8.5 代码审查修复（2026-11-17）

审查范围为本轮未提交改动及其共享调用边界，发现并修复两处问题，均先补充测试确认旧代码失败，再修改实现：

1. **AIG 手势接管顺序错误。** 平移的最后一个 pointermove 尚未执行动画帧时，滚轮或下一次平移会先推进 epoch，再取消旧手势，导致最后一段位移被丢弃；已绘制的平移则在 `is-panning` 仍存在时保存。现在先结束旧 pointer session、执行待处理的最后一帧并结算，再推进 epoch。Fit、resize、替换文档等显式重置仍先作废旧帧，不改变其接管语义。单测覆盖未绘制/已绘制两种路径、保存次数和过期 pointerup；Standard/ABC 浏览器测试追加真实滚轮接管及手势期间零保存断言。
2. **缺失画布时访问空缓存。** transform 观察回调遍历尚未挂载的 pane 时，`previous?.svg === svg` 可能因两者都为 undefined 而成立，随后读取 `previous.content` 抛异常。现在先确认缓存存在，再判断是否可以复用尺寸。单测保留真实 resize 的中心补偿断言，并加入同时存在已挂载与待挂载 pane 的情形。

这次审查没有改布局、路由、Scene 几何或 Simple，也没有改变正式性能样本和验收阈值；第 8.2 节仍为前一轮五轮对照，不将后续单轮功能复测混入提速比例。验证日志保存在远端候选目录的 `review_*.log`，Windows 构建与 smoke 记录保存在本地忽略目录的 `windows_review_*`。

### 8.6 4K 全图手势后续优化（2026-11-17）

本轮基线是 **8.5 审查完成后的工作树快照**，已包含选择轮廓和前面的面板/尺寸优化，不是 8.2 的 `48ea0ed`。阶段隔离目录为 `/home/wzh/my_code/netlistGraphBuilder/frontend_full_view_20261117/`。Simple 和整个 `src/layout/`、`src/render/` 相对本轮基线逐文件一致；没有引入持久裁剪、图层截图、布局重算或运行时依赖。

#### 分阶段实现

1. **滚轮调度。** 合并输入后，等最后一个变换帧绘制，再开始已有的 140ms 空闲等待，避免慢帧把等待时间耗尽、连续滚轮输入间反复恢复文字。代际令牌撤销过期计时器，只有状态切换时修改手势 class。显式 flush 同时清理排队帧、后续帧和计时器，不重复结算。
2. **平移及细节恢复。** 平移使用 `visibility:hidden` 保留文字排版，包括门类型文字；缩放暂用 `display:none` 省去文字缩放排版。完成态恢复全部文字、桥接和命中区域。SVG 根明确设置光标，避免捕获画布切换 grab/grabbing 时把继承样式变化传播到全部 SVG 子节点；Adjust 的移动光标单独保留。平移不再切换导线命中样式，指针捕获仍由画布持有。
3. **结束和接管。** `pointerSession.beforeEnd` 在撤销预览 class 前提交最后一帧，异常时仍清理捕获和样式，结算/保存发生在清理后。共享 pan 注册表确保滚轮、新 pan 或 Fit 结束旧 pan；Single/Compare 按下和 Fit 会 flush 排队滚轮。过期 pointermove/up 不能把 Fit 或缩放后的视口改回去。相关单测覆盖最后未绘制位移、取消、捕获丢失、失败清理及 Single/Compare Fit。

**测量修复：** 报告升级为 `measurementVersion: 2`。手势测量必须等最后一次输入对应的恢复双 rAF 完成；若新输入打断恢复，则丢弃旧恢复记录。旧脚本只等固定 350ms，可能在重型恢复结束前收样或把过期恢复记到新输入。基线和候选均使用同一新版观察器；下列恢复数值不能直接与 8.2 旧测量口径混算。额外报告“从最后输入到完整恢复”，包括空闲等待，避免把增加等待时间算作优化。
